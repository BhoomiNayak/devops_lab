Program 1

Introduction to Maven & Gradle

Overview of build automation tools, key differences, installation and environment setup

Theory

Build automation tools compile source code, run tests, manage dependencies, and package applications. Maven (XML-based, convention-over-configuration) and Gradle (DSL-based, high performance via caching) are the two dominant tools in the Java ecosystem.

AspectMavenGradle
Config filepom.xml (XML)build.gradle (Groovy/Kotlin)
PerformanceSlowerFaster — incremental builds + cache
FlexibilityConvention-drivenHighly customisable
Dependency repoMaven CentralMaven Central + custom
Learning curveGentlerSlightly steeper
Installing Maven (Windows)
1

Verify Java is installed

terminal
$java -version

Requires JDK 17 (recommended). Download from oracle.com if absent.

2

Download Maven ZIP

Go to maven.apache.org/download → Download the latest binary ZIP (e.g. apache-maven-3.9.9-bin.zip).

3

Extract & place folder

Extract the ZIP and move the folder to C:\Program Files\apache-maven-x.x.x

4

Set Environment Variables

Open Edit the system environment variables → Environment Variables

New System Variable
environment variable
Variable name: MAVEN_HOME Variable value: C:\Program Files\apache-maven-3.9.9
Edit PATH → Add new entry
path
C:\Program Files\apache-maven-3.9.9\bin
5

Verify installation

terminal
$mvn -version

Should print Maven version, Java version, and OS info.

Installing Gradle (Windows)
1

Download Gradle ZIP

Go to gradle.org/releases → Download binary-only ZIP (e.g. gradle-8.12.1-bin.zip).

2

Extract & place folder

Move extracted folder to C:\Program Files\gradle-8.12.1

3

Set Environment Variables

New System Variable
environment variable
Variable name: GRADLE_HOME Variable value: C:\gradle-8.12.1
Edit PATH → Add
path
C:\gradle-8.12.1\bin
4

Verify installation

terminal
$gradle -version

Should show Gradle version, Kotlin, Groovy, JVM info.

Working with Maven

Creating a Maven project, understanding pom.xml, dependency management and plugins

Create Maven Project (CLI)
terminal
$mvn archetype:generate -DgroupId=com.mvit -DartifactId=flipkart-app \ -DarchetypeArtifactId=maven-archetype-quickstart \ -DarchetypeVersion=1.4 -DinteractiveMode=false
groupId — org/domain identifier  |  artifactId — project name  |  -DinteractiveMode=false — skip prompts
pom.xml Key Elements
xml — pom.xml
<!-- Core identifiers --> <groupId>com.mvit</groupId> <artifactId>flipkart-app</artifactId> <version>1.0-SNAPSHOT</version> <packaging>jar</packaging> <!-- Dependency example --> <dependencies> <dependency> <groupId>junit</groupId> <artifactId>junit</artifactId> <version>4.11</version> <scope>test</scope> </dependency> </dependencies>
ScopeWhen available
compileAll phases (default)
providedCompile only — not bundled at runtime
runtimeRuntime only, not compile
testTest compilation and execution only

Program 3

Working with Gradle

Setting up a Gradle project, Groovy & Kotlin DSL, dependency management and task automation

Create Gradle Project
terminal
# In your project folder $gradle init
During gradle init you'll be prompted to select: build type → Application, language → Java, Java version → 17, DSL → Groovy (2) or Kotlin (1), test framework → JUnit 4 (1)
Build Scripts — Groovy vs Kotlin
Groovy DSL (build.gradle)
plugins {
    id 'application'
}
repositories {
    mavenCentral()
}
dependencies {
    testImplementation 'junit:junit:4.13.2'
    implementation libs.guava
}
application {
    mainClass = 'org.example.App'
}
Kotlin DSL (build.gradle.kts)
plugins {
    id("application")
}
repositories {
    mavenCentral()
}
dependencies {
    testImplementation("junit:junit:4.13.2")
    implementation(libs.guava)
}
application {
    mainClass = "org.example.App"
}
Groovy: dynamic, concise  |  Kotlin: statically-typed, better IDE support and compile-time error detection
Gradle Commands
1

Build the project

terminal
$gradle build

Compiles, tests, and creates output in build/libs/

2

Run the application

terminal
$gradle run
3

Run unit tests

terminal
$gradle test
4

Clean build outputs

terminal
$gradle clean
5

Run a custom task (Groovy example)

groovy — build.gradle
task printMessage { doLast { println 'This is a custom task automation' } }
terminal
# Run custom task: $gradle printMessage
Program 4

Maven → Gradle Migration

Build and run a Java app with Maven, then migrate the same project to Gradle

Part A — Build with Maven
1

Create Maven project

mvn archetype:generate -DgroupId=com.example -DartifactId=maven-project -DarchetypeArtifactId=maven-archetype-quickstart -DinteractiveMode=false
2

Edit App.java

Open src/main/java/com/example/App.java and write your program.

System.out.println("Hello Maven!"); System.out.println("This is the simple example");
3

Compile, test, package, run

cd maven-project mvn compile mvn test mvn package java -cp target/maven-project-1.0-SNAPSHOT.jar com.example.App
Part B — Migrate to Gradle
1

Run Gradle init inside Maven project folder

gradle init

Gradle detects the existing Maven build and prompts: "Found a Maven build. Generate a Gradle build from this?" → Type yes

Select DSL: 2 (Groovy)  →  New APIs: no

2

Update build.gradle — add application plugin

plugins { id 'java-library' id 'maven-publish' id 'application' // enables 'gradle run' } application { mainClass = 'com.example.App' }
3

Build and run with Gradle

gradle build gradle run

Output should match the Maven run — both print "Hello Maven!"

Verify migration: Maven output and Gradle output must be identical to confirm a successful migration.
Program 5

Introduction to Jenkins

Install Jenkins on Windows, configure for first use, unlock and explore the dashboard

What is Jenkins?

Jenkins is an open-source automation server for CI/CD. It automates building, testing, and deploying software. Key features include a vast plugin ecosystem, pipeline-as-code (Groovy DSL), and cross-platform support.

Install Jenkins on Windows
1

Verify Java

java -version
2

Download Jenkins installer

Go to jenkins.io → Download → Windows installer (.msi)

3

Run installer

Select "Run as Local System" → Choose port (default: 8080) → Click Test → Set Java path (e.g. C:\Program Files\Java\jdk-17\) → Click Next until install completes.

4

Access Jenkins in browser

http://localhost:8080
First-Time Setup
1

Retrieve initial admin password

# Open this file in Notepad and copy the password: C:\ProgramData\Jenkins\.jenkins\secrets\initialAdminPassword
2

Unlock Jenkins

Paste the password on the "Unlock Jenkins" page → Click Continue

3

Install suggested plugins

Select "Install suggested plugins" — wait for installation to complete

4

Create admin profile

Fill in username, password, full name, email → Save and Continue → Save and Finish → Start Using Jenkins

Program 7

Configuration Management with Ansible

Ansible basics — inventory, playbooks, modules. Write and run a basic playbook on WSL.

Ansible Components
ComponentDescription
InventoryFile listing target hosts (servers) Ansible will manage
PlaybookYAML file defining tasks to execute on target hosts
ModuleUnit of work — e.g. apt (package mgmt), service, copy, shell
Ad-hoc commandOne-off module call without a playbook
Lab Setup on WSL
1

Install WSL on Windows

# Run in PowerShell as Administrator: wsl --install
2

Install Ubuntu 22.04 from Microsoft Store

Open Ubuntu → create a UNIX username and password

3

Update packages & install Ansible

sudo apt update -y sudo apt install ansible -y ansible --version
Lab Execution
4

Create working directory

mkdir ansible-lab cd ansible-lab
5

Create inventory file

vi inventory.ini
Content of inventory.ini
[local] localhost ansible_connection=local

Save: press Esc then type :wq and hit Enter

6

Test connectivity

ansible all -i inventory.ini -m ping
Expected output
localhost | SUCCESS => { "changed": false, "ping": "pong" }
7

Create playbook to install htop

vi install_htop.yml
Content of install_htop.yml
--- - name: Install htop system monitor tool hosts: local become: true tasks: - name: Install htop package ansible.builtin.package: name: htop state: present
8

Run the playbook

ansible-playbook -i inventory.ini install_htop.yml
9

Verify htop is installed

htop

Interactive system monitor opens. Press q to exit.

Program 8

Jenkins CI + Ansible CD

Jenkins builds Maven project; Ansible deploys the generated JAR to local server

Part A — Jenkins CI
1

Create Maven project & push to GitHub

git init git add . git commit -m "Initial commit" git branch -M main git remote add origin <GitHub_Repo_URL> git push -u origin main
2

Configure Jenkins Freestyle job

New Item → Freestyle → SCM: Git (paste repo URL) → Build Trigger: Poll SCM H/5 * * * *

Build → Invoke top-level Maven targets
Goals: clean compile test package
Windows Batch Command
java -cp target/your-app-1.0-SNAPSHOT.jar com.mvit.App
3

Archive the JAR artifact

Post-build action → Archive the artifacts

Files to archive: target/*.jar
Part B — Ansible CD
4

Install Ansible in WSL

sudo apt update -y sudo apt install ansible -y
5

Create inventory & deploy playbook

mkdir ansible-lab && cd ansible-lab vi inventory.ini
inventory.ini
[local] localhost ansible_connection=local
vi deploy.yml
deploy.yml
--- - name: Deploy JAR from Jenkins hosts: local become: true tasks: - name: Copy JAR file copy: src: /mnt/c/ProgramData/Jenkins/.jenkins/workspace/<job>/target/your-app.jar dest: /home/<username>/ansible-lab/app.jar mode: '0755' - name: Run JAR file shell: nohup java -jar /home/<username>/ansible-lab/app.jar > app.log 2>&1 &
6

Run the playbook

ansible-playbook -i inventory.ini deploy.yml
7

Verify deployment

cat app.log

Should show application output e.g. "Hello welcome to Devops lab"

Manifest error? Add maven-jar-plugin to pom.xml with <mainClass>com.mvit.App</mainClass>, then git push to trigger a new Jenkins build.
